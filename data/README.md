# TrueIntent — Dataset Sourcing & Usage

Datasets used to train and evaluate the ML modules. `data/raw/` is gitignored: nothing here is
committed except small curated seed files under `data/`.

## Module A: authorized IEEE-CIS ingestion

Only `train_transaction.csv` is used: 590,540 rows, 20,663 fraud (3.50%). The generator copies
`amount` and the `isFraud` label in the original source unit, retains `TransactionID` and
`TransactionDT` for audit and chronological splitting, and writes a `feature_contract` marker plus
SHA-256 provenance. It generates **no** synthetic call/device flags and reads no card or address
columns. The historical `ml/module_a_priors.json` (hypothetical label-conditioned telemetry priors)
was deleted: it is incompatible with the amount-only contract and had no readers.

Because the licensed source is absent from a fresh clone, Module A has **no trained artifact and no
current metrics**. `/check-transaction` returns 503 in that state rather than a substituted score.
See [Module A correctness](../docs/MODULE_A_CORRECTNESS.md).

## Module B: verified source and reproduction

The [Kaggle dataset](https://www.kaggle.com/datasets/shashwatwork/web-page-phishing-detection-dataset)
is public and downloadable without authentication, version 2, last updated June 27, 2021, under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Credit: Abdelhakim Hannousse and Salima
Yahiouche, *Web page phishing detection*,
[Mendeley Data V3, DOI 10.17632/c2gw7fy2j4.3](https://data.mendeley.com/datasets/c2gw7fy2j4/3);
Kaggle mirror published by Shashwat Tiwari. Collection date: **May 2020**.

This is **not** a mirror of UCI Phishing Websites (327). The
[UCI dataset](https://archive.ics.uci.edu/dataset/327/phishing+websites) is public, CC BY 4.0,
with 11,055 rows of numeric features, unsuitable for raw-URL character TF-IDF. The downloaded Kaggle
CSV has 11,430 rows: raw `url`, 87 extracted features, and `status`. Only `url` and `status` are
retained, with `status` renamed `label`. Unknown labels, missing URLs and conflicting labels are
rejected. URL whitespace is stripped and lowercase duplicates removed because the vectorizer
lowercases its input. No URLs are visited during ingestion, training or tests.

```powershell
.\.venv\Scripts\python.exe ml\generate_module_b_data.py
.\.venv\Scripts\python.exe ml\train_module_b.py
.\.venv\Scripts\python.exe -m pytest tests\test_module_b.py tests\test_module_b_classifier.py -q
```

Offline ingestion of a verified download:
`ml\generate_module_b_data.py --source data\raw\module_b_source_kaggle_v2.zip`. An upstream CSV with
`url,status` or canonical `url,label` is also accepted; local files require independently verified
provenance.

| Artifact | SHA-256 |
|---|---|
| Source ZIP | `0bf65a186d58f312c2ed74c686eae418e6debb8b916f27079dbc718f3f1d1c02` |
| Generated CSV | `588f85c75146706a255e8001738b75323443cd062a3c19896df24a999428374f` |

Metadata lives beside the CSV; metrics go to `ml/models/module_b.metrics.json`. Raw data and the
`.pkl` model remain gitignored, so a fresh checkout needs the commands above. Restart a running
backend after retraining to clear its in-memory model cache.

**No Module B production-training rows or features are synthetic.** The dataset holds 5,715
legitimate and 5,712 phishing URLs. Synthetic `.example` URLs appear only in isolated unit tests,
never in this dataset, the saved model, or any reported evaluation.

Full metrics, the registered-domain-disjoint split and per-model latency: see
[Module B evaluation](../docs/MODULE_B_EVALUATION.md) and `data/README.md` history in git.

**PhishTank supplement omitted.** Its [developer page](https://www.phishtank.org/developer_info.php)
still documents hourly bulk CSV/JSON downloads, descriptive User-Agent requirements and
application keys. However, its [terms page](https://phishtank.org/terms.php) now labels the old
free-data terms **archived** and points to
[Cisco's current terms](https://www.cisco.com/c/en/us/about/legal/cloud-and-software/end_user_license_agreement.html).
Permission for this ML-training use under the current terms is unclear, so no feed was downloaded
or blended in and current phishing coverage is not claimed.

## Module C: real text, weak behavioural labels, authored extensions

Sources: UCI SMS Spam Collection (CC BY 4.0) and five short cited incident excerpts in
`data/module_c_fear_sources.json`. The assembled set has 4,607 public rows (4,502 ham mapped to
`benign`, weak-labelled corpus rows mapped to `other_fraud`) plus 117 authored/translated rows from
`data/module_c_intent_seeds.json`. No invented text pads the public corpus.

Passing `--skip-emails` excludes the Kaggle *Fraudulent E-mail Corpus* (CC BY-SA 4.0) and records a
different source population in the metadata; the current artifact was built with emails excluded.

The author of `data/module_c_fear_sources.json` also maintains the per-class evaluation, license
distinctions and reproduction steps in the [Module C datasheet](MODULE_C_DATASHEET.md). Authored
Hindi/Hinglish rows are diagnostics on synthetic text, not real-language recall.

## Module D: synthetic interaction scenarios

`data/raw/module_d_interaction_scenarios.csv` is regenerated deterministically from
`ml/evaluate_module_d.py` (seed 42) and needs no external data. Labels come from a hand-written
policy over simulated scores, not observed incidents. See the
[Module D datasheet](MODULE_D_DATASHEET.md) — those metrics are not real-world performance.
